# MVP：台灣鳥類觀察

最小可行性產品文件。依課程「怎麼寫 MVP？」的 10 個區塊整理，更新於 2026-10-27。

主軸：**救傷為主，資料是工具**（2026-10-27 定案）。

---

## 1. 專案目標（要解決什麼問題）

很多人遇到落地或受傷的鳥不知道怎麼做：救傷中心收到的鳥有四到六成是沒受傷、還在學飛的幼鳥，被好心的人撿走了；網路上的處理方式又很分散，甚至互相矛盾。
本專案提供有出處的救傷指引，並用台灣近期的觀察資料判斷鳥屬於哪個類群，讓猛禽、鷺鷥、早熟型水鳥等需要特別處理的鳥得到對應的提醒。

## 2. 目標使用者（誰會用、在什麼情境用）

- 在路邊、校園、公園看到鳥掉在地上，不確定要不要撿、該打給誰的人
- 情境：通常拿著手機、就在鳥旁邊、很緊張，需要快速看到「先做什麼、打哪支電話」

## 3. 核心假設（MVP 要驗證什麼）

| # | 假設 | 驗證方式 | 狀態 |
|---|---|---|---|

| H2 | 只靠 API 回傳的分類資料（目、科、學名），就能判斷一隻鳥該顯示哪一種救傷提醒 | 用 SQL 查各科筆數，對照網頁上各類群判斷出的筆數 | ✅ 已驗證（鷺科 364 筆、早熟型 293 筆對得上） |

## 4. MVP 功能（第一版一定要做的）

**資料流**
- fetch.py：從 iNaturalist 抓台灣鳥類觀察 → 查目、科 → 清理 → 去重寫入 MySQL → 記錄 fetch_log
- export.py：從 MySQL 匯出成 web/data.js
- stats.sql：9 段統計與資料品質檢查

**網頁**
- 首頁最上方是救傷入口：撥號按鈕＋三張情境卡片，不用先知道鳥名
- 下方「不知道是什麼鳥？從近期觀察找找看」：照片卡片列表、搜尋、顯示更多
- 詳細視窗：大圖、分類、地點、照片授權、原始紀錄連結
- 遇到牠怎麼辦：
  - 三張情境卡片（雛鳥、幼鳥、受傷或生病）＋詳細特徵對照表
  - 依類群顯示黃色提醒框（猛禽、鷺鷥類、早熟型水鳥、鴿子），每隻鳥最多一個；有黃色框的鳥，一般做法預設收起
  - 救傷專線（0800-000-930、1999、1959）、資料來源

## 5. 不做什麼（防止專案暴走）

- 哺乳類或其他物種
- eBird 等其他資料來源
- 地圖
- 每日自動排程（資料改為手動執行 fetch.py、export.py 更新）
- 縣市篩選、獨立統計頁、月份分布圖
- 使用者帳號、留言、回報功能
- 排除死亡個體（API 參數測試無效）
- 自動合併「不同帳號上傳同一張照片」的重複紀錄（只佔約 0.25%，合併會誤刪真實資料）
- 沒有來源支持的類群提醒（例：雉鴴科、彩鷸科雖是早熟型，但查無來源，不加黃色框）
- 給水方法、臨時鳥巢、猛禽與鷺鷥的抓取方式（台灣來源彼此矛盾或建議民眾不要自行接觸）

## 7. 資料來源（從哪裡來、格式如何）

**觀察資料**：iNaturalist API（JSON，讀取不需金鑰）
- `GET /v1/observations`：台灣（place_id 7887）、鳥類、研究級、有照片、照片授權 cc0／cc-by／cc-by-nc、中文名稱
- `GET /v1/taxa/{ids}`：用祖先分類編號查出目、科的中文名

**救傷內容**：台灣來源 21 個（台北市野鳥學會、林業保育署、農業部、各縣市動保處、中華民國野鳥學會、科博館、新聞報導等），國外來源 12 個（Audubon、Cornell Lab、RSPB、野生動物復健中心等）。清單見網頁「查看資料來源」。

## 8. 技術架構

- Python 3.12：requests、PyMySQL
- MySQL（以 MySQL Workbench 建表、查詢）
- 前端：HTML、CSS、原生 JavaScript（不使用框架、不從網路載入函式庫）
- 版本控制：Git、GitHub

```
iNaturalist API → fetch.py → MySQL ─┬→ export.py → web/data.js → 網頁
                                    └→ stats.sql（統計、品質檢查）
```
